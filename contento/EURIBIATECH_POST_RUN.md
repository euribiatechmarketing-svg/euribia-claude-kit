# Weekly Euribiatech post: run brief

One run = one Euribiatech showcase carousel (5–7 frames, 1080×1350) about ONE system we built, handed to Dimitar for review.
Read `ENGINE_RULES.md` first, then `EURIBIATECH_POSTS.md`. They win over this file on detail.

1. **Pick the project:** the next one in the catalogue in `EURIBIATECH_POSTS.md` that has no
   "euribiatech-post" entry in `state/ledger.json` in the last 90 days. Prefer internal products; ask before NDA-sensitive client work.
2. **Collect facts:** the project's README / deck / portfolio overview page. Pull: the problem, how it works (3 steps), 2–3 technical details worth showing, the stack, and any measured number with how it was measured. Never invent numbers.
3. **Collect real screens:** from the Portfolio Figma file (`ntGiZvpbLcUhR2759P7mTr`) or the project's own assets. Export the parts you need (desktop hero, one detail screen, one mobile screen). Convert to PNG.
4. **Write the copy in Bulgarian:** cover headline (2 lines, one accent word), problem, 3-step system map, annotated feature, metrics, CTA. Technical, concrete, no hype, no em-dashes.
5. **Build:** clone the `ET Master · …` frames from Reference into a new row in Results on page Euribiatech Posts. Set copy and screens, place annotation markers next to the details they explain.
6. **Verify every frame by screenshot.** Check for overlaps, single words alone on a line, unreadable text, lorem ipsum and real personal data.
7. **Export** 01–0N.png and caption.txt to `~/Documents/01-Euribia/posts/euribiatech/<YYYY-MM-DD>-<slug>/`.
8. **Hand over** with `submit_for_review` (client "Euribiatech", the PNGs in order, the caption, the Figma link, one line of notes). Publish nothing yourself.
9. **Ledger:** add an entry with type "euribiatech-post", project, date, Figma ids and sources.

If a step fails twice, finish what you can and say in the first line exactly what did not get done.
