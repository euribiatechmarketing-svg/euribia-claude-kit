# Работна инструкция на оператора (човек + AI агенти)

Последна проверка: 11.11.2026

Услугата се изпълнява от един AEO оператор с Claude Code. Операторът не е нужно да е SEO специалист. Агентът върши измерването, одита, черновите и техническите промени. Човекът решава, одобрява, говори с клиента и поема отговорността за всяко число в отчета.

## Инструментът: aeo-tracker

Папка: `~/Euribiatech/internal projects/AEO-SEO Service/aeo-tracker/` (споделеното репо). Без зависимости, работи с Node 20+.

| Команда | Какво прави | Цена |
|---|---|---|
| `node aeo.mjs doctor` | Проверява ключовете и инструментите | 0 |
| `node aeo.mjs init <клиент> --site URL --brand "Име"` | Създава `clients/<клиент>/client.json` и `portfolio-v1.csv` | 0 |
| `node aeo.mjs audit <клиент> --geo` | Технически одит: robots.txt по бот, CDN, HTML без JS, H1, мета, schema, llms.txt, sitemap, ключови страници, платформа | 0 |
| `node aeo.mjs track <клиент> --dry-run` | Показва колко заявки и колко USD ще струва | 0 |
| `node aeo.mjs track <клиент>` | Задава въпросите на ChatGPT, Perplexity, Gemini, Claude (по 3 пъти) и прави отчета | ~12-13 USD на клиент за 30 въпроса (измерено 11.11.2026) |
| `node aeo.mjs report <клиент>` | Преизчислява отчета без нови заявки (след промяна на алиаси или конкуренти) | 0 |
| `node aeo.mjs deck <клиент>` | Презентация `.pptx` от `report.json` | 0 |

Данните отиват в `local.json` → `dataDir` (за Марио: OneDrive `AEO-SEO-Service/Source/tracker-data/`). Всеки run има `results.jsonl` (сурови отговори), `report.json` (за дашборда, схема `euribiadigital.aeo-report/v1`), `report.md`, `answers.csv` и `.pptx`.

Ключове (само в Keychain, никога във файл):

```bash
security add-generic-password -a "$USER" -s OPENROUTER_API_KEY -w
```

Командата пита за стойността. Същото за `GOOGLE_AI_API_KEY` и `TYPESAFE_API_KEY`. Тракерът ги чете сам.

## Кой какво прави

| Задача | AI агент (Claude Code) | Човек (оператор) |
|---|---|---|
| Разпознаване на платформата | `audit` го казва; отваря `platforms/<платформа>.md` | Потвърждава с клиента кой поддържа сайта |
| Портфолио от въпроси | Чернова от `prompt-portfolio-bg.md`, сайта и конкурентите | Сверява с продажбите на клиента, одобрява v1 |
| Базова линия и месечно измерване | `track`, `report`, `deck` | Чете отговорите в `answers.csv`, проверява 5 случайни реда на ръка |
| Google AI Overviews / AI Mode, Copilot | Няма API | Ръчна проверка на 10-те ключови въпроса в инкогнито от България, записва в `work.json` |
| Грешни факти | Събира изреченията за марката (`report.md`, последната секция) | Решава кое е грешно и откъде идва |
| Технически промени | Пише JSON-LD, llms.txt, мета текстове, robots.txt; на WordPress/Shopify/Wix през API или като готов текст; на custom/vibe-coded като PR | Одобрява всяка промяна преди публикуване |
| Съдържание | Чернова на страница по шаблона (отговор в първите редове, таблица, FAQ, дата, автор) | Добавя реалните факти, цени и пример от клиента; `humanizer` преди публикуване |
| Присъствие извън сайта | Списък на цитираните домейни и какво има там | Профили, отзиви, публикации: само реални, никакви фалшиви |
| Отчет към клиента | `deck` + `work.json` | Пише "Накратко" със собствени думи, представя на срещата |

## Месечен цикъл (6-8 часа на клиент)

| Седмица | Стъпки | Време |
|---|---|---|
| 1 | `audit`, `track`, `report`. Проверка на контролните въпроси. Ръчна проверка в Google AI Mode и Copilot | 1,5 ч |
| 1 | Журнал на грешните факти. Поправка на източника | 1 ч |
| 2-3 | Техническите поправки от одита (по playbook-а на платформата) | 1-2 ч |
| 2-3 | Една нова или обновена страница, която отговаря на въпрос от ядрото | 2 ч |
| 4 | Едно действие извън сайта (каталог, профил, публикация) | 1 ч |
| 4 | `work.json`, `deck`, кратка среща или имейл с клиента | 1 ч |

## work.json (какво е свършено този месец)

Файл `clients/<клиент>/work.json`. Влиза в отчета и в дашборда:

```json
{
  "done": ["Organization schema на началната страница", "Нова страница: Колко струва ремонт на баня в София"],
  "next": [{ "action": "H1 и мета описание на 6-те страници за услуги", "owner": "EuribiaDigital", "due": "02.12.2026" }],
  "manualChecks": [{ "engine": "Google AI Mode", "question": 1, "mentioned": false, "date": "2026-11-11" }]
}
```

## Правила за качество (преди всеки отчет)

1. Контролните въпроси: ако "винаги" не е 100% или "никога" не е 0%, асистентът е сменил поведението си. Пишем го в отчета и не отчитаме разликата като наш резултат.
2. Пет случайни реда от `answers.csv`: съвпада ли колоната `mentioned` с текста? Ако марката се пише по друг начин, добавяме алиас в `client.json` и пускаме `report` (безплатно).
3. Колоните "Препоръчани" идват от TypeSafe Jev с праг 50%. Преглеждаме граничните случаи (40-60%).
4. Грешките (`errors` в отчета) трябва да са 0. Иначе пускаме `track` отново със същия `--run` и той довършва само липсващите.
5. Разходът се записва в отчета. Ако мине 15 USD на клиент на месец, режем до 20 въпроса или 2 пъти.
6. Никакви обещания за позиция. Никакви измислени числа: ако не е измерено, пише "не е измерено".
7. API отговорите не са същите като в приложенията (памет, локация, модел). Това се казва в методологията на всеки отчет.

## Достъпи, които искаме от клиента (минимум)

| Платформа | Искаме | Не искаме |
|---|---|---|
| Всички | Google Search Console (пълни права), Bing Webmaster Tools, GA4 (четене), Google Business Profile (мениджър) | Пароли на собственика |
| Wix | Покана като сътрудник с права за SEO и редакция | Собственик на сайта |
| WordPress | Потребител с роля Editor; за API: Application Password на отделен потребител | Administrator, FTP, хостинг |
| Shopify | Staff акаунт с права за Online Store (теми, страници, блог) | Плащания, поръчки, клиенти |
| Custom / vibe-coded | Достъп до git репото (PR, не директно в main) или до проекта в Lovable/Vercel | Сървър, база данни |
